## What to build

任务 2 之后窗口能生效，但只能靠登录服务器手改 auth 文件。这一片让运营者在自有内嵌伴随页上直接编辑窗口。

运营者打开伴随页，每个账号一行多出一个窗口输入框；填入 `18:00-09:00` 保存即生效；清空则恢复全天可用；填了非法值立刻在该行看到明确的报错，而不是保存成功后静默摘号。

按 ADR 0003 的既定约定，能力加在**自有伴随页**上，不碰那个从外部仓库自动覆盖的管理面板。

## Key interfaces

- 管理接口的字段更新端点 — 请求体新增窗口字段。行为遵循既有 `note` 字段的形状（而非 `claude_usage_mode` 的形状）：

  | 输入 | 行为 |
  |---|---|
  | 空串 | 双删 Metadata 与 Attributes（恢复全天，与 priority/note 的清除约定一致）|
  | 合法窗口 | 双写 Metadata 与 Attributes |
  | 非法 | 400，消息直接给出期望格式 |
  | 字段省略 | 完全不动该账号的现有窗口 |

  双写的理由与 `claude_usage_mode` 相同：Metadata 是落盘的事实来源，Attributes 是调度层优先读取的内存镜像。

- 校验所用的解析 — **必须复用任务 2 在调度层写的那个解析函数，不得在管理端另写一份**。两份解析器迟早会对 `"18:00-18:00"` 给出不同答案，届时 UI 说保存成功而调度层判它非法（或反之）。调度层在公开 sdk 包内，管理端导入无障碍。

- 伴随页表格 — 新增一列窗口。单元格内是一个文本输入框，保存沿用页面上既有下拉框的"变更即提交"交互，错误回显到所在行、不影响其他行。

  **用单个文本框而非两个时间控件**：跨午夜场景下两个独立控件会诱导人把它理解成两个无关字段，而整串 `18:00-09:00` 更贴合"这是一段窗口"的心智，也与后端单键形态一一对应。

- 页面的账号标识 — 注意本项目的 auth 列表暴露**多个不可互换的标识符**：字段更新端点匹配的是账号 id/文件名，而按凭证发起上游调用用的是另一个运行时索引。本任务走的是字段更新端点，因此用 id/文件名，与页面上既有的模式切换开关一致。

## Known data variants

输入框接收的是运营者手打的自由文本，写入侧必须对任务 2 列出的全部非法形态返回 400：分隔符写错（`~`、中文破折号、带空格）、格式写错（`6pm-9am`、只有一半）、数值越界（`25:00`、`18:60`）、以及 `start == end`。前后空白应被接受并正常保存。

空串与纯空白都表示"清除"，两者行为必须一致。

## Acceptance criteria

- [ ] 提交合法窗口后，Metadata 与 Attributes 都被写入，且调度立即按新窗口生效
- [ ] 提交空串（或纯空白）后，两处都被删除，账号恢复全天可用
- [ ] 提交任意非法窗口返回 400，且消息中给出期望格式
- [ ] 请求体省略该字段时，账号已有的窗口不被改动
- [ ] 管理端的校验与调度层使用同一个解析实现——同一个字符串在两处的合法性判断永远一致
- [ ] 伴随页表格出现窗口列，输入框预填账号当前窗口（未配置则为空）
- [ ] 在输入框中修改并触发保存后，页面反映保存结果；失败时错误回显在该行
- [ ] 某一行保存失败不影响其他行的展示与操作
- [ ] 页面 HTTP smoke 可见新列
- [ ] 伴随页仍受既有的控制面板开关门控（面板关闭时页面 404）

## Out of scope

- 开/关徽章与下次开门时刻的展示（任务 5）——本任务只做编辑
- 列表接口的派生字段（任务 5）；本任务只需列表原样回吐 `available_window` 供输入框预填
- 不碰外部管理面板，不 fork、不注入外部 HTML（ADR 0003）
- 不改动既有的 usage-mode 切换开关与配额展示
- 不为 gemini/codex 账号提供 UI 入口：字段与调度层是 provider 无关的，但本轮 UI 只在 Claude 伴随页暴露
- 不引入 JS 测试框架
