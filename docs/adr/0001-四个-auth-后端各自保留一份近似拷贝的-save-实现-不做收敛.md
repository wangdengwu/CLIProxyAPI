# ADR 0001 — 四个 auth 后端各自保留一份近似拷贝的 Save 实现，不做收敛

**Status:** accepted

`FileTokenStore`、`PostgresStore`、`ObjectTokenStore`、`GitTokenStore` 的 `Save` 是四份结构几乎相同的代码。它们看起来该合并，但错误信息前缀各不相同，落盘之后的步骤也各不相同：Postgres 要 upsert 数据库记录、Git 要提交并推送、对象存储要上传、文件存储什么都不做。合并是一次独立重构，风险和范围都远超任何一次借道修改。

代价是这四份会漂移，而且已经漂移过：只有文件存储在 storage 分支上注入了元数据，另外三份完全没有，导致调用方准备好的元数据在生产实际运行的 Postgres 后端上被直接丢弃（2026-08-17 重绑丢失运营者字段的根因）。

**因此：任何改动 `Save` 语义的需求，都必须把四处一起改，并逐个 diff 确认。只改一两处就是在制造下一次同类 bug。**
