# ADR 0003 — 运营界面缺口用自建内嵌伴随页补，不去改外部控制台

**Status:** accepted

> **2026-09-30 修订**：下面「外部资产照常自动更新」的前提已只对逃生舱路径成立 —— 默认路径的
> `management.html` 现在也 `go:embed` 进本二进制，见 [ADR 0005](0005-控制面板资产随本仓库发布-不跟第三方-latest.md)。
> 本 ADR 的决定（不 fork 外部面板、缺口用自建内嵌伴随页补）不受影响。

`management.html` 是从外部仓库 `router-for-me/Cli-Proxy-API-Management-Center` 的 Release 拉取、每约 3 小时按 SHA256 自动覆盖的资产 —— 本地改动会被冲掉，也进不了它的发布流程。因此当需要一个外部面板没有的运营控件时，不 fork、不注入外部 HTML，而是在本二进制里 `go:embed` 一个自己的页面、挂到自有路由（如 `/usage-mode.html`）。

约定：HTML 本身不鉴权返回（照 `management.html` 的服务方式，在 `disable-control-panel` group 之外），页面 JS 用同一个管理密钥（`SecretKey`/`MANAGEMENT_PASSWORD`/本地密码，`Authorization: Bearer`）调 `/v0/management/*`；用 `RemoteManagement.DisableControlPanel` 同步门控（面板关则伴随页也 404）。这样外部资产照常自动更新、我们零 fork，缺口能力完全自持、可增量追加下一个控件。

> **2026-10-16 修订**：决定本身（不 fork 外部面板、用自建内嵌伴随页补缺口）继续成立，但「页面 JS 用同一个管理密钥」+「HTML 本身不鉴权返回」两个约定被打破：

> - 新增 `remote-management.companion-secret` 单独门住 `/usage-mode.html` 与新加的 `/v0/management/companion/*` 端点（`CompanionAuthMiddleware`）。management key 不能用，门进入伴随页；反之 companion key 进不了 `/v0/management/*` 任何路由（含 OAuth、logs、config）。两把钥匙互不接受、互不代替，覆盖了更广的威胁面。
> - 首装默认页面打开（companion-secret 为空），由伴随页上的「设置锁」表单写入；这与 `disable-control-panel` 的「默认关、显式开」反向，原因是首装运营者唯一的入口就是伴随页本身。
> - 新增 Operator-set-key `claude_pin_to_lowest` 由伴随页独占读 / 写：标准 `/v0/management/auth-files` 列表不返回该字段、PATCH 字段白名单不接受该字段（外显管理面板 manage.html 完全看不到、也写不了）。Companion key 与 management key 都拿不到这条键的写权；只能通过伴随页的两条新端点（`/v0/management/companion/claude-pin-states` 的 GET 与 POST）。

> 这两条都是「缺口由伴随页自持」原则的下一处自然落点：新能力先放伴随页、不 fork 外部面板。伴随着 Operator-set-keys 家族的扩展，未来伴随页会继续承担「manage.html 看不到的新 Operator 键」的入口。
