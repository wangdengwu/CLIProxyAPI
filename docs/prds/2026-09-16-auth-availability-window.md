# 账号可用时间段（PRD）

## Problem

共享出来的 Claude 账号是同事个人的号。同事白天自己要用，只愿意在下班后把号借给代理池；现在代理池没有任何"什么时候可以用这个号"的表达能力，一旦账号进了池子就是 7×24 被调度，同事白天自己用的时候会撞上额度已经被池子吃掉。

结果是共享意愿被压制：想借号的人只能靠"白天手工停用、晚上手工启用"来兑现承诺，或者干脆不共享。运营者也没有任何地方能看出"这个号现在到底该不该被用"。

## Solution

给每个账号加一个可选的**可用时间段**：只有落在时间段内，这个账号才会被调度器选中。

- 不配 = 全天可用，与今天行为完全一致。
- 配了就只在窗口内参与调度，窗口外对调度器完全不可见（硬门禁，不是降级、不是低优先级）。
- 窗口可以跨午夜，`18:00-09:00` 表示"下午六点到次日早九点"。
- 运营者在自有伴随页上直接编辑窗口，并能一眼看到每个号**此刻**是开还是关、下次什么时候开门。
- 如果某一刻所有账号都关门，客户端拿到的错误会带上"下次开门时间"，而不是一个没有信息量的"无可用账号"。
- 有一个全局开关，出问题时一键让所有窗口失效、全部账号回到全天可用。

## User Stories

1. 作为共享账号的同事，我想指定"只在 18:00–次日 09:00 借出我的号"，这样白天我自己用的时候额度不会被代理池吃掉。
2. 作为共享账号的同事，我想在不配置任何时间段时保持今天的行为（全天可借），这样已有账号不需要任何改动就能继续工作。
3. 作为运营者，我想在伴随页上为任意账号填写可用时间段并即时生效，这样我不必登录服务器手改 auth 文件。
4. 作为运营者，我想清空某个账号的时间段以恢复全天可用，这样撤销一次配置和撤销 priority/note 一样简单。
5. 作为运营者，我想在伴随页上看到每个账号**此刻**是开还是关，这样我不用心算跨午夜窗口和时区。
6. 作为运营者，我想看到关门账号的**下次开门时刻**，这样我能判断"现在容量少"是暂时的还是配错了。
7. 作为运营者，我想在窗口字符串写错时立刻收到明确的报错，这样一个 typo 不会静默地把账号从池子里摘掉。
8. 作为运营者，我想即使手工改坏了 auth 文件，该账号也退回"全天可用"而不是"永久关门"，这样失败方向永远偏向服务可用。
9. 作为运营者，我想用一个全局开关一键停用整个时间段功能，这样窗口逻辑或时区配错导致高峰期批量关门时，我不必逐个账号去清字段。
10. 作为运营者，我想窗口的时区由服务端统一配置且默认北京时间，这样容器的 UTC 本地时区不会把 18:00 悄悄变成凌晨 2 点。
11. 作为运营者，我想改完窗口或全局配置后热加载即生效，这样调整共享策略不需要重启服务。
12. 作为运营者，我想重新登录/重新绑定账号后窗口配置仍然存在，这样刷新凭证不会清掉我的运营意图。
13. 作为 API 客户端，我想在所有账号都关门时收到带"多久后恢复"的错误，这样我能决定退避重试还是直接失败。
14. 作为运营者，我想窗口外的账号仍然在后台正常刷新 token，这样账号关门一整夜之后开门时凭证依然有效。
15. 作为运营者，我想时间段这个能力不绑定 Claude、不绑定 shared 模式，这样以后 gemini/codex 账号想用同一套语义时无需再改调度层。

## Implementation decisions

### 数据形态

auth 文件新增一个顶层运营者键 `available_window`，值为字符串 `"HH:MM-HH:MM"`。缺失或空串表示全天可用。

它加入 CONTEXT.md 定义的 **Operator-set-keys** 家族（与 `claude_usage_mode`/`priority`/`note` 并列），因此自动继承既有的跨登录保留机制——该机制按"旧文件顶层键减去新 payload 已定义的键"保留，新字段无需登记白名单。

选单键字符串而非 start/end 双键或对象，原因是合成器把 auth 元数据读进的 `Attributes` 是 `map[string]string`，只有裸字符串能零摩擦通过现有管道；同时单键消除了"只配了一半"的非法中间态。合成器新增一段与 `claude_usage_mode` 同形的读取，`Auth` 上新增一个与 `ClaudeUsageMode()` 同款的访问器（Attributes 优先、回落 Metadata）。

**不支持多段窗口**（见 Out of scope）。

### 解析与语义

`start` 与 `end` 各自归一化为"当天第几分钟"：

- `start < end`：同日窗口。
- `start > end`：跨午夜窗口。
- 区间取**左闭右开**：窗口 `18:00-09:00` 在 18:00 整已开门、09:00 整已关门。与既有 `claudeIsNight` 的比较约定一致。

判为非法的输入：格式不是 `HH:MM-HH:MM`、时或分越界、以及 `start == end`（`"18:00-18:00"` 语义歧义，不猜测）。

**失败方向：非法一律 fail-open**——运行时视为全天可用并打 warning 日志。硬门禁的每一次误判都是静默摘号，所以运行时永远偏向"放行"，而把拦截 typo 的责任交给写入侧的 400 校验。

### 配置

新增顶层配置节 `auth-availability`，与 `claude-ratelimit-alert` 平级：

```yaml
auth-availability:
  enabled: true              # kill switch，默认 true
  timezone: "Asia/Shanghai"  # 窗口锚定时区，默认上海
```

`enabled: false` 时所有窗口失效、全部账号回到全天可用。时区加载失败回落 `Asia/Shanghai` 而非系统本地时区——容器的本地时区通常是 UTC，回落到它会静默偏移 8 小时。两个字段都接入既有的配置热加载 diff（那里已在 diff `default-usage-mode`）。

刻意与 `claude-ratelimit-alert.timezone` 解耦：该能力已定为 provider 无关、mode 无关，依赖一个 Claude 专用配置节会形成层次错位。

### 调度门禁

判定点落在 `isAuthBlockedForModel`——这是所有 selector（round-robin 与 fill-first）唯一的过滤收口，也是"账号此刻属不属于池子"这个问题的自然归属。插入位置在 `Disabled` 检查**之后**、`RatelimitBlockUntil` 检查**之前**：窗口不依赖任何运行时状态，最先短路最省事。

判定的短路顺序（四条路径里三条是 fail-open，刻意如此）：

1. 全局开关关闭 → 不拦
2. 窗口字段为空 → 不拦
3. 解析失败 → 不拦 + warning
4. 否则按配置时区判窗口

**配置如何到达判定点。** 判定点是包级函数，调用链 `Pick → getAvailableAuths → collectAvailableByPriority → isAuthBlockedForModel` 全程没有配置，而 `Pick` 是公开的 `Selector` 接口方法，加参数会破坏接口与所有自定义 selector。因此采用**包级配置快照 + atomic 存取**：`Manager.SetConfig` 时把 `(enabled, 已解析的 location)` 存为不可变快照，判定点直接读。这与该包既有的 `activeRatelimitTarget` 全局注册模式同构（`ApplyRatelimitBlock` 正是靠它找到 Manager）。

时区字符串只在 `SetConfig` 时解析一次。加载时区会读文件系统，绝不能放在每次选号的热路径上。快照需要非 nil 初值（`enabled: true` + 上海），避免配置尚未加载时读到 nil。

### 全部关门时的错误

新增一个 block reason `blockReasonWindowClosed`，不复用既有的"其他"原因。这是必须的：`getAvailableAuths` 只对被计入冷却计数的原因返回"带恢复时间"的错误，判成"其他"会掉进没有任何时间信息的 `no auth available`。因此该原因要与冷却原因一样计入计数、并参与"最早恢复时刻"的取最小值。

错误本身新增一个与既有模型冷却错误并列的构造，复用同样的"带 resetIn"结构但文案讲明是可用时间段之外——既有文案说的是模型冷却，用来表达"账号下班了"会误导排障。

**下次开门时刻**的计算与 UI 徽章共用同一个函数，两处不会漂移。必须在目标时区里按日期构造时刻，不能对当前时间做固定小时数加减——夏令时切换日的一天不是 24 小时，虽然上海当前无 DST，但配置允许填任何时区。

### 两条红线

- **绝不改动 `Disabled` 标志。** 后台 token 刷新只看 `Disabled`，不走调度过滤。用它实现关门会让账号整夜不刷新 token，开门时凭证已过期——功能会在最不该失败的时刻失败。
- **绝不改动 `RatelimitBlockUntil`。** 那是限流的持久状态；窗口是纯计算、无状态，改完下次选号立即生效，因此不需要 `claude_usage_mode` 翻成 dedicated 时那种"清除拦截块"的配套动作。

### 管理端契约

`PATCH /v0/management/auth-files/fields` 请求体新增 `available_window`，行为遵循 `note` 的形状：

| 输入 | 行为 |
|---|---|
| 空串 | 双删 Metadata/Attributes（恢复全天，与 priority/note 的清除约定一致）|
| 合法窗口 | 双写 Metadata/Attributes |
| 非法 | 400，文案直给期望格式 |

校验**必须复用调度层那个解析函数**，不得在管理端另写一份——两份解析器迟早对 `"18:00-18:00"` 给出不同答案。调度层在公开 sdk 包内，管理端导入无障碍。

`ListAuthFiles` 的每个条目新增三个字段：原样回吐的 `available_window`，以及两个**服务端算好**的派生字段 `available_now`（布尔）与 `next_open_at`（带时区偏移的时间戳，开门时省略）。派生字段由服务端算是因为窗口锚定配置时区，而浏览器时区是任意的，前端自算会在跨时区办公或 UTC 容器里给出错误答案。

窗口为空、或全局开关关闭时，一律 `available_now: true` 且省略 `next_open_at`——这样 UI 会如实反映"功能被关了，谁都不受限"，而不是显示一堆其实不生效的"关门"。

### UI

沿用 ADR 0003 的既定约定：能力加在自有内嵌伴随页上，不碰自动覆盖的外部管理面板。

伴随页表格增加一列，单元格内是窗口文本输入框加一个开/关徽章，保存沿用既有下拉框的"变更即提交"交互，错误回显到所在行。

用单个文本框而非两个时间控件：跨午夜场景下两个独立控件会诱导人把它理解成两个无关字段，而整串 `18:00-09:00` 更贴合"这是一段窗口"的心智，也与后端单键形态一一对应。

## Testing decisions

三个接缝，都复用既有的测试骨架。刻意**不为窗口解析函数单独写一层单测**：解析的每个分支——跨午夜、左闭右开边界、各类非法输入 fail-open——都能从调度行为上观察到（非法窗口的可观察行为就是"不拦"），单独测解析器等于把测试绑在实现上，重构即碎。

**接缝 ① 调度行为**（sdk 认证包内，直接调用调度过滤与候选收集函数）。现有的限流拦截测试已经在用这个接缝直接调用调度过滤函数，照抄其形状。表驱动覆盖：

- 同日窗口与跨午夜窗口的内外判定，含 18:00 整开门、09:00 整关门两个边界时刻
- 全部非法输入（格式错、时分越界、start==end）均**不拦**
- 字段缺失、空串均不拦
- 全局开关关闭时完全不拦
- **默认配置下的行为**（不配 `auth-availability` 时等价于开启 + 上海时区）——用行为验证默认值，而不是断言配置结构体字段
- 窗口外被拦时 reason 是新增的那一个，且**所有账号关门时返回的是带时间的错误而非无信息的"无可用账号"**（这是本 PRD 最关键的单条回归防线）
- 并发读配置快照 + 热加载写入的竞态用例，在 race 检测下跑

时间全部靠注入 `now`，不依赖真实时钟。

**接缝 ② 管理端 HTTP**（管理处理器测试）。既有的 usage-mode 管理测试有 7 个用例的完整模板，照抄：合法值双写、空串双删、非法值 400、字段省略时不动原值、列表接口吐出三个新字段（含窗口为空与开关关闭两种情况下的派生字段取值）。

**接缝 ③ UI**。项目无 JS 测试设施。沿用本仓库已验证过的做法：把纯展示/解析逻辑包进标记块，用一次性脚本**从发布文件里逐字抽取**该块来跑断言（抽取而非拷贝，所以不会漂移），加上既有的伴随页服务测试做 HTTP smoke 确认新列存在。最后在 lab 上留一次浏览器确认。

**已知盲区**：跨午夜窗口只能靠注入时间来验证，测不到"服务器真的跑到 09:00 那一刻"的时钟推进。真实时钟相关的缺陷靠接缝 ① 的 race 用例兜底。

## Out of scope

- **多段窗口**（如"18:00–09:00 且午休 12:00–13:00 也开放"）。当前需求是单段，多段会让解析与 UI 都显著变复杂。
- **每账号独立时区**。时区是全局配置。跨时区同事共享是假想需求。
- **按星期几区分**（工作日/周末不同窗口）。
- **窗口关门时掐断进行中的请求**。判定只发生在选号时刻，已经选中的请求（含长流式）跑完为止。
- **软降级语义**（窗口外降优先级或收紧限流阈值）。本次明确定为硬门禁。
- **在外部管理面板上暴露该能力**。按 ADR 0003，只做自有伴随页。
- **为 gemini/codex 账号提供 UI 入口**。字段与调度层已做成 provider 无关，但本轮 UI 只在 Claude 伴随页暴露。
